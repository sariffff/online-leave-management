## ปัญหาที่พบ เรียงตามความรุนแรง

### 🔴 วิกฤต

**1. ฐานข้อมูลเปิดให้ใครก็อ่าน/เขียนได้ (RLS ปิดอยู่)** — `SEC-leaverequest`, `SEC-users`, `SEC-userrole`, `SEC-write`, `SEC-login-user`
- ใช้แค่ anon key (ซึ่งอยู่ในโค้ดฝั่งเบราว์เซอร์ ใครก็เห็น) อ่านตาราง `leaverequest`, `users`, `userrole` ได้ และ**เขียน**ตาราง `holiday` ได้ (HTTP 201)
- ผู้ใช้ที่ล็อกอินแล้วอ่านใบลาของคนอื่นตรง ๆ ผ่าน Supabase ได้ (อ่านใบลาของ teacherA ได้ 4 แถวด้วย token ของ teacherB)
- ทางแก้ที่เตรียมไว้แล้ว: รัน `supabase/migrations/001 → 002 → 003` (ยังไม่ได้รัน)
- ส่วนที่ปลอดภัยแล้ว: ไฟล์แนบใน Storage อ่านตรง ๆ ไม่ได้ (`SEC-storage` ผ่าน)

**2. ลบ "ระดับชั้น" 1 รายการ → ห้องเรียน รายวิชา และคาบในตารางสอนที่ใช้มันถูกลบตามไปหมด** — `CR-level-6`
- API ตอบ 200 และฐานข้อมูลจริงลบแบบ CASCADE: ห้องเรียน ✗, รายวิชา ✗, คาบสอน ✗ (ทดสอบด้วยข้อมูล `__test__` แยกเฉพาะ)
- `supabase/schema.sql` **ไม่มี** `ON DELETE CASCADE` → ฐานข้อมูลจริงตั้งค่าไม่ตรงกับไฟล์ schema
- เสี่ยงข้อมูลหายจำนวนมากจากการกดลบครั้งเดียว (ประวัติสอนแทนที่ผูกกับคาบอาจหายตามด้วย — ยังไม่ได้ทดสอบชั้นนั้น)
- ส่วนการลบ "กลุ่มสาระ" ที่ครูใช้อยู่ ถูกกันไว้ถูกต้อง (409)

### 🟠 สูง

**3. ดึงวันหยุดราชการจาก Google ไม่ได้เลย → นับวันลาผิด และผู้ใช้ปลอมจำนวนวันได้** — `HO-02`, `AC-19`, `LV-12`, `HO-01`
- log เซิร์ฟเวอร์: `google fetch failed 2026 invalid_grant: Invalid JWT Signature` ทุกครั้ง → คีย์ service account ที่ใช้อยู่ใช้ไม่ได้แล้ว (ถูกลบ/rotate ใน Google Cloud)
- ผล: ลา 12–16 เม.ย. 2027 (มีสงกรานต์ 3 วัน) ระบบคิด **5 วัน** แทน 2 วัน
- ร้ายกว่านั้น: เมื่อดึงวันหยุดไม่ได้ ระบบ**เชื่อตัวเลข `total_day` ที่ส่งมาจากเบราว์เซอร์** (ถ้าไม่เกินวันทำการสูงสุด) → ยื่นลา 2 วันแต่ส่ง `total_day=0.5` ระบบบันทึก 0.5 วัน = **โกงโควตาได้** (`lib/leave/workflow.ts` `resolveTotalDays`)
- ประสิทธิภาพ: เมื่อ Google ล้มเหลว ระบบไม่จำผลล้มเหลวไว้ จึงลองใหม่ทุกคำขอ เสียเวลา ~170–200ms ต่อคำขอที่ใช้วันหยุด

**4. ตารางรายการแสดงแค่ 1 แถวในหน้าแรก (เมื่อไม่ระบุ pageSize)** — unit `V-02b`, `PF-03`; E2E `SV-02`, `SSR-01`, `SSR-03`
- สาเหตุ: `toInt(null, fallback)` ใน `lib/validate.ts` → `Number(null)` = 0 ซึ่งเป็นตัวเลขที่ "ถูกต้อง" จึงไม่ใช้ fallback แล้วถูกบีบเป็นค่าต่ำสุด 1
- ผล: หน้าที่ส่งข้อมูลมากับ HTML ทั้ง 8 หน้า (ประวัติการลา, คิวตรวจ, คิวอนุมัติ, รายการลาวิชาการ ฯลฯ) **แสดง 1 รายการ และจำนวนหน้า = จำนวนรายการ** จนกว่าผู้ใช้จะกดเปลี่ยนหน้า/กรอง
- กระทบ API ที่ไม่ส่ง `pageSize` ด้วย: `/api/supervisor/leave-review`, `/api/academic/substitution-history` (ตอบ `pageSize: 1`) ฯลฯ
- เกิดจาก refactor เมื่อวาน (ข้อ "ส่งข้อมูลมากับ HTML") — ตอนนั้นตรวจแค่ typecheck/build ไม่ได้ทดสอบหลังล็อกอิน

**5. ยื่นใบลาซ้อนวันเดิมได้** — `LV-13`
- ยื่นลา 16–17 พ.ย. ซ้ำกับใบที่รออยู่ ระบบรับ (201) และกันโควตาซ้ำ 2 เท่า ไม่มีการตรวจช่วงวันทับกัน

**6. ระบบเสนอและให้มอบหมาย "ครูที่ลาอยู่" เป็นครูสอนแทน** — `AC-10`, `AC-11`

### 🟢 ต่ำ

**11. error 500 และเปิดเผยข้อความภายในของฐานข้อมูล** — `DR-11`, `SEC-headers`

เมื่อมีบัญชี admin จริง สคริปต์จะ: ล็อกอินจริง → สร้างกลุ่มสาระและบัญชีทดสอบทุกบทบาท**ผ่าน API หน้าจอ admin** (แทน service key) → รันทุกเคสเดิม + RA-01..07 (บทบาท, เปิดหน้า admin 9 หน้า, จำนวนผู้ใช้/ข้อมูลหลักตรงกับฐานข้อมูล, เปิดตารางสอนของครูทุกคน, ไม่มีสิทธิ์เกินบทบาท) — **ไม่แก้ข้อมูลของบัญชี admin จริงหรือข้อมูลจริงใด ๆ** เทสที่ต้องแก้ตัวเอง (ถอดสิทธิ์/ปิดบัญชีตัวเอง) ใช้บัญชี admin ทดสอบแทน

> แนะนำ: เปลี่ยนรหัสผ่าน admin หลังทดสอบ (รหัส 5 ตัวอักษรถูกเดาได้ง่าย และถูกพิมพ์ในแชทแล้ว)

## สิ่งที่ทำงานถูกต้อง (ผ่านทั้งหมด)

- **ความปลอดภัยระดับแอป:** API 62 รายการตอบ 401 เมื่อไม่ล็อกอิน; ตาราง "บทบาท × API" ครบ 5 บทบาท + ผู้ไม่มีบทบาท ไม่มีช่องรั่ว; ปลอม cookie `active_role` ไม่ได้ผล; หน้าเว็บ 21 หน้า × 5 บทบาท redirect ไป `/403` ถูกต้อง
- **บัญชีผู้ใช้:** สร้าง/แก้/ปิด/เปิด/ลบ; ปิดใช้งานแล้ว session เดิมใช้ไม่ได้ทันทีและล็อกอินใหม่ไม่ได้; เปลี่ยนบทบาทมีผลทันที; กันลบ/ปิด/ถอดสิทธิ์ตัวเอง; กันลบผู้ที่มีประวัติ; สร้างซ้ำไม่ทิ้งข้อมูลค้าง
- **ใบลา:** ตรวจวันที่/ปีงบ/เสาร์-อาทิตย์/ประเภท/เหตุผล; ไฟล์ผิดชนิด/ใหญ่เกิน → 422 และไม่เหลือใบลาค้าง; ตัดวันหยุดสถานศึกษาถูกต้อง; ครึ่งวัน; แก้ไขแล้วคำนวณวันใหม่; เปลี่ยนไฟล์แล้วไฟล์เก่าถูกลบ; แก้/ลบของคนอื่นไม่ได้
- **ขั้นตอนอนุมัติ:** pending → failed → แก้ → pending → reviewed → approved/rejected → covered; กดซ้ำได้ 409; **กดพร้อมกัน 2 คน สำเร็จคนเดียว**; ผอ.ลบใบ reviewed ได้ ลบใบ approved ไม่ได้
- **โควตา:** used/reserved/ไม่จำกัด/วันสะสม/ปีงบ พ.ศ.; snapshot `userleavequota` ตรงกับค่าที่คำนวณ
- **ตารางสอน/สอนแทน:** กันคาบซ้ำ, กันสอนแทนตัวเอง, วันไม่ตรงตาราง, มอบหมายซ้ำ, ปิดงานเมื่อครบ, ประวัติสอนแทน
- **อื่น ๆ:** ค้นหาด้วยอักขระพิเศษไม่พัง (กัน filter injection), signed URL ใช้ได้จริง, logout ตัด session ทุกเครื่อง

## ความเร็ว (production บนเครื่องนี้ → Supabase)

- API แบบอ่าน (GET) ค่ากลาง **~173ms** ต่อคำขอ, การตรวจสิทธิ์ใน layout ของหน้า ~72–80ms
- ช้าสุด: แก้ใบลา 701ms, ยื่นใบลา 630ms, ปิดงานสอนแทน 622ms, สร้างใบลาโดย ผอ. 541ms — ทุกตัวเรียก Google (ล้มเหลว ~170ms) + คำนวณโควตา 2 รอบ
- ถ้าแก้ข้อ 3 (คีย์ Google) เวลาของคำขอที่ใช้วันหยุดจะลดลงประมาณ 170ms
