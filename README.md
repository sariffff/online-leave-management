# ระบบลาออนไลน์ — โรงเรียนบ้านตาสา

ระบบยื่นและอนุมัติใบลาของบุคลากรแทนการลาแบบกระดาษ ใช้ได้ทั้งคอมพิวเตอร์ แท็บเล็ต และมือถือ

```
บุคลากรยื่นใบลา → ธุรการตรวจสอบ → ผู้อำนวยการอนุมัติ → ฝ่ายวิชาการจัดครูสอนแทน
```

มีโควตาวันลาตามปีงบประมาณ (1 ต.ค. – 30 ก.ย.) คำนวณวันลาโดยตัดเสาร์-อาทิตย์และวันหยุดให้อัตโนมัติ พิมพ์ใบลาเป็น PDF ได้ และผู้ดูแลระบบปรับการตั้งค่าต่าง ๆ ได้จากหน้าเว็บโดยไม่ต้องแก้โค้ด

**เทคโนโลยี:** Next.js 15 (App Router) · React 19 · TypeScript · Supabase (PostgreSQL, Auth, Storage) · Tailwind CSS 4 · shadcn/ui

## บทบาทผู้ใช้

ผู้ใช้หนึ่งคนมีได้หลายบทบาท เลือกบทบาทที่จะใช้งานหลังเข้าสู่ระบบ

| บทบาท | ทำอะไรได้ |
|---|---|
| **บุคลากร** | ยื่นใบลา (แนบไฟล์ได้), ดู/แก้ไข/ลบใบลาที่ยังไม่ถูกพิจารณา, ดูวันลาคงเหลือ, แดชบอร์ดส่วนตัว, พิมพ์ใบลา PDF |
| **ธุรการ** | ตรวจสอบใบลา "ผ่าน / ไม่ผ่าน" (ไม่ผ่านต้องระบุเหตุผล), ประวัติการตรวจสอบ |
| **ผู้อำนวยการ** | อนุมัติ / ไม่อนุมัติ (ไม่อนุมัติต้องระบุเหตุผล), สร้างใบลาแทนบุคลากร, ประวัติ, แดชบอร์ดสถิติทั้งโรงเรียน |
| **วิชาการ** | ดูคาบที่ต้องหาครูสอนแทนของใบลาที่อนุมัติแล้ว, มอบหมาย / เปลี่ยน / ยกเลิกครูสอนแทน, ปิดงานเมื่อครบทุกคาบ, ประวัติการสอนแทน |
| **ผู้ดูแลระบบ** | จัดการบุคลากรและบทบาท, กลุ่มสาระ, รายวิชา, ระดับชั้น, ห้องเรียน, ตารางสอน, วันหยุด และ **ตั้งค่าระบบ** |

## ขั้นตอนของใบลา

```
pending ──ธุรการผ่าน──▶ reviewed ──ผอ.อนุมัติ──▶ approved ──จัดสอนแทนครบ──▶ covered
(รอพิจารณา)            (รออนุมัติ)              (อนุมัติ)                 (จัดสอนแทนแล้ว)
   │                       │
   └─ไม่ผ่าน─▶ failed      └─ไม่อนุมัติ─▶ rejected
      (ผู้ยื่นแก้ไขแล้วส่งใหม่ → pending)
```

- ผู้อำนวยการสร้างใบลาแทนบุคลากรได้ ใบที่สร้างจะอนุมัติทันที
- ถ้าวิชาการยกเลิกการมอบหมายสอนแทนของใบที่ปิดงานแล้ว ใบลาจะกลับเป็น `approved` เพื่อจัดใหม่
- ทุกการเปลี่ยนสถานะเป็นการ update แบบมีเงื่อนไข (`WHERE status = สถานะเดิม`) กันการกดซ้ำหรือสองคนกดพร้อมกัน

## กฎที่ระบบตรวจให้ (ที่ระบบหลังบ้านทุกข้อ ไม่ใช่แค่บนหน้าเว็บ)

- **จำนวนวันลา** คำนวณที่เซิร์ฟเวอร์เสมอ ตัดเสาร์-อาทิตย์และวันหยุด รองรับลาครึ่งวันเช้า/บ่าย (บางประเภทตั้งให้นับรวมวันหยุดได้ เช่น ลาคลอด)
- **โควตา** ยื่นเกินสิทธิ์คงเหลือไม่ได้ · ยอดใช้ = ใบที่อนุมัติแล้ว, ยอดกันไว้ = ใบที่รอพิจารณา · ประเภทที่ไม่ได้กำหนดวันต่อปี = ไม่จำกัด · รองรับวันลาสะสมจากปีก่อน
- **ใบลาทับกัน** คนเดียวกันยื่นช่วงวันซ้อนกันไม่ได้ (ครึ่งเช้า + ครึ่งบ่ายวันเดียวกันได้)
- **กฎของแต่ละประเภทการลา** (ตั้งค่าได้): ลาได้ครั้งละไม่เกินกี่วัน, ลาเกินกี่วันต้องแนบเอกสาร, ต้องยื่นล่วงหน้ากี่วัน, ยื่นย้อนหลังได้กี่วัน, ลาครึ่งวันได้หรือไม่, ปิดใช้งาน
- **ไฟล์แนบ** ขนาด จำนวน และชนิดไฟล์ตามที่ตั้งค่าไว้
- **สอนแทน** มอบหมายได้เฉพาะครูที่ว่างในคาบนั้นและไม่ได้ลา, ครูเจ้าของคาบต้องมีใบลาที่อนุมัติแล้วครอบคลุมคาบนั้น, ข้ามวันหยุดและคาบในครึ่งวันที่ไม่ได้ลา
- **ลบข้อมูลหลัก** ลบผู้ใช้ที่มีประวัติการลาไม่ได้ (ให้ปิดใช้งานแทน), ลบกลุ่มสาระ/ระดับชั้น/รายวิชาที่ยังถูกใช้อยู่ไม่ได้

## ตั้งค่าระบบ (ผู้ดูแลระบบ)

เมนู "ตั้งค่าระบบ" แบ่งเป็น 5 หมวด ทุกการแก้ไขบันทึกประวัติ (ใครแก้อะไร เมื่อไร ค่าเดิม → ค่าใหม่) และย้อนกลับได้

| หมวด | ตั้งค่าอะไรได้ |
|---|---|
| ทั่วไป | ชื่อระบบ, ชื่อโรงเรียน, ตำแหน่งผู้อนุมัติในใบลา, โลโก้, ข้อความท้ายเมนู, สีของระบบ |
| ประเภทการลา | เพิ่ม / แก้ไข / ปิดใช้งาน / ลบ / เรียงลำดับ, วันลาต่อปี, วันสะสม, กฎการลา, คำอธิบายและสี |
| คาบเรียน | จำนวนคาบ, เวลาแต่ละคาบ, เวลาเริ่มช่วงบ่าย (เลือกปรับเวลาในตารางสอนเดิมได้) |
| ไฟล์แนบ | ขนาดไฟล์สูงสุด, จำนวนไฟล์, ชนิดไฟล์ที่รับ |
| ประวัติการแก้ไข | ดูและย้อนกลับ (รายการที่เป็นการย้อนกลับจะย้อนซ้ำไม่ได้) |

มีปุ่ม "คืนค่าเริ่มต้นทั้งระบบ" เลือกได้ทีละหมวด และย้อนกลับได้จากประวัติ

การตั้งค่าเก็บเป็นไฟล์ JSON ใน Supabase Storage bucket ส่วนตัว `app-config` (ระบบสร้างให้เองเมื่อใช้งานครั้งแรก) ส่วนข้อมูลหลักของประเภทการลาอยู่ในตาราง `leavetype`

## วันหยุด

- **วันหยุดราชการ** ดึงจากปฏิทินวันหยุดไทยสาธารณะของ Google (ไฟล์ .ics ไม่ต้องใช้คีย์) เก็บเฉพาะ "วันหยุดนักขัตฤกษ์" จำไว้ 6 ชั่วโมง
- **วันหยุดสถานศึกษา** ผู้ดูแลเพิ่มเองในหน้า "จัดการวันหยุด"
- ปฏิทินสาธารณะมักยังไม่มีวันหยุดทางจันทรคติของปีถัดไปจนกว่าจะประกาศ — ถ้าต้องการล่วงหน้าให้เพิ่มเองในหน้าจัดการวันหยุด

## โครงสร้างโค้ด

```
app/
  (auth)/          เข้าสู่ระบบ, เลือกบทบาท
  (user)/          ยื่นลา, ประวัติ, วันลาคงเหลือ, แดชบอร์ด
  (supervisor)/    ตรวจสอบใบลา, ประวัติการตรวจ
  (director)/      อนุมัติ, ประวัติ, แดชบอร์ด
  (academic)/      จัดสอนแทน, ประวัติสอนแทน, ตารางสอน
  (admin)/         ข้อมูลหลัก, ตารางสอน, วันหยุด, ตั้งค่าระบบ
  api/             API ทั้งหมด (ทุก route ห่อด้วย route([...]) ตรวจสิทธิ์ก่อนเสมอ)
components/
  shell/           โครงหน้า (เมนู, หัวเว็บ, ค่าตั้งค่าที่ส่งลงทุกหน้า)
  shared/          ตารางใบลา, ตัวกรอง, หน้าต่างพิจารณา, หน้าต่างยืนยัน, ช่องวันที่แบบไทย
  admin/ user/ director/ academic/   คอมโพเนนต์เฉพาะบทบาท
  ui/              คอมโพเนนต์พื้นฐาน (shadcn/ui)
lib/
  http.ts          route() — ตรวจ session/บทบาท/บัญชีที่ปิดใช้งาน และรูปแบบ error เดียวกันทั้งระบบ
  guard.ts         ตรวจผู้ใช้และบทบาทจากฐานข้อมูล
  leave/           workflow (เปลี่ยนสถานะ), days (นับวัน), quota, rules (กฎการลา), types, files, queries
  services/        holidays, schedule (คาบสอนแทน/ครูว่าง), authUsers
  settings*.ts     การตั้งค่าระบบ (รูปแบบ + ค่าเริ่มต้น + ตรวจค่า + เก็บ/อ่าน + ประวัติ)
  admin/           CRUD ข้อมูลหลัก, จัดการผู้ใช้
  client/          ฟังก์ชันฝั่งเบราว์เซอร์ (apiFetch, usePagedQuery, ...)
supabase/
  schema.sql       โครงสร้างฐานข้อมูล
  migrations/      SQL ที่ต้องรันตามลำดับ
middleware.ts      ต่ออายุ session และพาผู้ที่ยังไม่เข้าสู่ระบบไปหน้า login
```

**ความปลอดภัย**
- สิทธิ์ตรวจจากฐานข้อมูลทุกครั้ง ไม่เชื่อค่าจากเบราว์เซอร์ (cookie `active_role` ใช้แค่เลือกเมนู)
- API ใช้ service role หลังตรวจสิทธิ์แล้ว ส่วนฐานข้อมูลเปิด RLS กันการเรียกตรงด้วย anon key
- ไฟล์แนบอยู่ใน bucket ส่วนตัว เปิดผ่านลิงก์ชั่วคราว (5 นาที) เท่านั้น

## ติดตั้งและรันในเครื่อง

ต้องมี Node.js 22 ขึ้นไป

```bash
npm install
cp .env.example .env.local   # แล้วใส่ค่าจริง
npm run dev                  # http://localhost:3000
```

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `npm run dev` | รันโหมดพัฒนา |
| `npm run build` / `npm start` | build และรันแบบ production |
| `npm run lint` | ตรวจโค้ดด้วย ESLint |
| `npm run typecheck` | ตรวจ TypeScript |

### ตัวแปรสภาพแวดล้อม

| ตัวแปร | จำเป็น | ใช้ทำอะไร |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | ✅ | URL ของโปรเจกต์ Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | ✅ | anon key (ใช้ตอนเข้าสู่ระบบ) |
| `SUPABASE_SERVICE_ROLE_KEY` | ✅ | **ใช้ฝั่งเซิร์ฟเวอร์เท่านั้น** ห้ามตั้งชื่อขึ้นต้นด้วย `NEXT_PUBLIC_` |
| `HOLIDAY_ICS_URL` | – | เปลี่ยนแหล่งวันหยุดราชการ (ค่าเริ่มต้น = ปฏิทินวันหยุดไทยของ Google) |
| `PERF_LOG` | – | `1` = แสดงเวลาที่ใช้ของแต่ละ API ใน log (โหมด dev เปิดให้อัตโนมัติ) |

### ฐานข้อมูล

ตั้งโปรเจกต์ใหม่: รัน `supabase/schema.sql` แล้วรันไฟล์ใน `supabase/migrations/` ใน SQL Editor ของ Supabase **ตามลำดับนี้** (ทุกไฟล์รันซ้ำได้)

| ลำดับ | ไฟล์ | ทำอะไร |
|---|---|---|
| 1 | `…0001_helpers_revoke_anon_storage.sql` | ฟังก์ชันตรวจบทบาท, ถอนสิทธิ์ anon, policy ของไฟล์แนบ |
| 2 | `…0002_rls_policies.sql` | กฎการเข้าถึงข้อมูลทุกตาราง |
| 3 | `…0005_fk_restrict.sql` | กันลบข้อมูลแล้วข้อมูลที่ผูกกันหายตามไปด้วย |
| 4 | `…0004_constraints_and_indexes.sql` | กันข้อมูลซ้ำ + index ให้ค้นหาเร็ว |
| 5 | `…0006_leavetype_sequence.sql` | ให้รหัสประเภทการลาใหม่ไม่ชนของเดิม |
| 6 | `…0003_enable_rls.sql` | เปิด RLS |

ข้อมูลตั้งต้นที่ต้องมี: ตาราง `roletype` (1 admin, 2 user, 3 supervisor, 4 director, 5 academic) และ `leavetype`
บัญชีผู้ดูแลคนแรก: สร้างผู้ใช้ใน Supabase Auth → เพิ่มแถวใน `users` และ `userrole` (role 1) → เข้าสู่ระบบแล้วจัดการผู้ใช้อื่นจากหน้าเว็บ

## Deploy บน Vercel

1. Import repository นี้ใน Vercel (Framework = Next.js, ไม่ต้องแก้ build command)
2. ใส่ตัวแปรสภาพแวดล้อมตามตารางด้านบนใน **Settings → Environment Variables**
3. ใน Supabase **Authentication → URL Configuration** ตั้ง Site URL เป็นโดเมนของ Vercel
4. แนะนำให้ตั้ง **Function Region** ของ Vercel ให้ใกล้กับ region ของ Supabase (เช่น Singapore `sin1`) เพื่อให้ตอบเร็ว

ฟอนต์ภาษาไทยของใบลา PDF อยู่ที่ `public/fonts/Sarabun-*.ttf`
